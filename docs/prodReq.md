## 1. Executive Summary

NovaCart is a rapidly growing online retailer operating in 30+ countries. The company recently completed a major data engineering initiative that centralized and validated business data into **Snowflake Gold tables**. Although the data is now trusted and readily available, account managers continue relying on manually generated Excel reports that are outdated by at least one week.

The objective of this project is to develop a **web-based dashboard** that provides account managers with **real-time access** to sales, customer, and product information through an intuitive interface. The solution will eliminate manual reporting requests, reduce delays in obtaining business insights, and improve operational efficiency.

### Key Objectives
- ✅ Reduce dependence on manual reporting by 90%
- ✅ Provide near real-time visibility (< 1 minute data freshness)
- ✅ Enable self-service analytics for 50+ account managers
- ✅ Deploy within one-week timeline
- ✅ Build scalable foundation for future enhancements

## 5. Functional Requirements

### FR-1: Orders Overview Dashboard

**Priority:** P0 (Critical)

**Description:**  
The application shall display a comprehensive orders overview dashboard showing order trends, revenue patterns, and geographic distribution.

**Components:**

#### 1.1 Summary Stat Cards
Display three key metrics at the top of the page:

| Metric | Calculation | Format |
|--------|-------------|--------|
| **Total Revenue** | `SUM(amount) WHERE status IN ('delivered', 'shipped')` | Currency with 2 decimals (e.g., "$1,284,750.00") |
| **Total Orders** | `COUNT(DISTINCT order_id) WHERE status IN ('delivered', 'shipped')` | Integer with comma separators (e.g., "8,432") |
| **Unique Customers** | `COUNT(DISTINCT customer_id) WHERE status IN ('delivered', 'shipped')` | Integer with comma separators (e.g., "380") |

> **Critical Business Rule:** Only orders with `status IN ('delivered', 'shipped')` are included in revenue and order count calculations. Pending, cancelled, and returned orders are excluded.

#### 1.2 Monthly Revenue Chart
- **Chart Type:** Bar chart or line chart (using Recharts library)
- **Data Source:** `GET /franchise/orders` endpoint
- **X-Axis:** Month (format: "January", "February", etc.)
- **Y-Axis:** Revenue (currency format)
- **Tooltip:** Display month name, order count, and revenue
- **Responsive:** Chart scales to container width

#### 1.3 Revenue by Country Chart
- **Chart Type:** Horizontal bar chart (using Recharts library)
- **Data Source:** `GET /franchise/countries` endpoint
- **X-Axis:** Revenue (currency format)
- **Y-Axis:** Country name (for US data: shows "City, State")
- **Sorting:** Descending by revenue (highest at top)
- **Tooltip:** Display country/city, order count, and revenue

#### 1.4 Date Range Filter
- **Filter Controls:**
  - Start Date picker (format: YYYY-MM-DD)
  - End Date picker (format: YYYY-MM-DD)
  - "Apply" button to execute filter
- **Default Values:** 
  - Start: 2022-01-01
  - End: 2022-12-31
- **Behavior:**
  - Changes do not apply until "Apply" button is clicked
  - Both charts update simultaneously when filter is applied
  - Stat cards (summary) always show total data regardless of filter

**Acceptance Criteria:**
- [ ] All three stat cards display correct values from summary endpoint
- [ ] Monthly revenue chart displays bars/lines for each month in date range
- [ ] Revenue by country chart displays top locations by revenue
- [ ] Date range filter updates both charts when Applied
- [ ] Error states display user-friendly messages
- [ ] Loading states display while data is being fetched

## 6. Technical Specifications

### 6.1 Data Model

#### Table: `fact_orders`
Order transaction fact table (30,000 records).

| Column | Data Type | Description | Example |
|--------|-----------|-------------|---------|
| `order_id` | INTEGER | Unique order identifier | 1001 |
| `customer_id` | INTEGER | Foreign key to dim_customer | 234 |
| `product_id` | INTEGER | Foreign key to dim_product | 5 |
| `date_key` | INTEGER | Foreign key to dim_date | 20220315 |
| `quantity` | INTEGER | Number of units ordered | 2 |
| `amount` | DECIMAL(10,2) | Order amount in local currency | 149.99 |
| `status` | VARCHAR(20) | Order status | delivered, shipped, pending, cancelled |
| `order_date` | DATE | Date order was placed | 2022-03-15 |

**Key Business Rules:**
- Revenue calculations: `status IN ('delivered', 'shipped')`
- Date range filtering: Use `order_date` column

#### Table: `dim_customer`
Customer dimension table (400 records) with full history tracking.

| Column | Data Type | Description | Example |
|--------|-----------|-------------|---------|
| `customer_id` | INTEGER | Customer identifier | 234 |
| `name` | VARCHAR(100) | Customer full name | John Smith |
| `email` | VARCHAR(100) | Email address | john.smith@example.com |
| `city` | VARCHAR(50) | City | San Francisco |
| `state` | VARCHAR(2) | State code (US) | CA |
| `is_current` | BOOLEAN | Current record flag | TRUE |

**Key Business Rules:**
- Always filter `is_current = TRUE` for current customer data
- Address display format: US data shows "City, State"; international varies

#### Table: `dim_product`
Product catalog dimension table (15 records).

| Column | Data Type | Description | Example |
|--------|-----------|-------------|---------|
| `product_id` | INTEGER | Product identifier | 5 |
| `name` | VARCHAR(100) | Product name | Wireless Mouse |
| `category` | VARCHAR(50) | Product category | Electronics |
| `price` | DECIMAL(10,2) | Current list price | 29.99 |

#### Table: `dim_date`
Date dimension table for time-series analysis (365+ records).

| Column | Data Type | Description | Example |
|--------|-----------|-------------|---------|
| `date_key` | INTEGER | Primary key (YYYYMMDD format) | 20220315 |
| `full_date` | DATE | Actual date | 2022-03-15 |
| `year` | INTEGER | Year | 2022 |
| `quarter` | INTEGER | Quarter (1-4) | 1 |
| `month` | INTEGER | Month number (1-12) | 3 |
| `month_name` | VARCHAR(20) | Month name | March |
| `day_of_week` | INTEGER | Day of week (1=Sunday, 7=Saturday) | 3 |

**Relationships:**
```
fact_orders.customer_id → dim_customer.customer_id
fact_orders.product_id → dim_product.product_id
fact_orders.date_key → dim_date.date_key
```

#### Endpoint 3: Franchise Summary
```
GET /franchise/summary
```

**Description:** Returns overview statistics for all orders in the database.

**Query Parameters:** None (always returns full dataset)

**Response 200 (Success):**
```json
{
  "total_revenue": 1284750.00,
  "total_orders": 8432,
  "unique_customers": 380,
  "date_range": {
    "start": "2022-01-01",
    "end": "2022-12-31"
  }
}
```

**Business Logic:**
- `total_revenue`: `SUM(amount) WHERE status IN ('delivered', 'shipped')`
- `total_orders`: `COUNT(DISTINCT order_id) WHERE status IN ('delivered', 'shipped')`
- `unique_customers`: `COUNT(DISTINCT customer_id) WHERE status IN ('delivered', 'shipped')`
- `date_range`: `MIN(order_date)` and `MAX(order_date)` from all orders

#### Endpoint 4: Monthly Orders
```
GET /franchise/orders?start={start_date}&end={end_date}
```

**Description:** Returns monthly order volume and revenue for the specified date range.

**Query Parameters:**

| Parameter | Type | Required | Default | Format | Example |
|-----------|------|----------|---------|--------|---------|
| `start` | string | No | 2022-01-01 | YYYY-MM-DD | 2022-01-01 |
| `end` | string | No | 2022-12-31 | YYYY-MM-DD | 2022-12-31 |

**Response 200 (Success):**
```json
[
  {
    "month": "2022-01",
    "month_name": "January",
    "order_count": 842,
    "revenue": 128450.00
  },
  {
    "month": "2022-02",
    "month_name": "February",
    "order_count": 910,
    "revenue": 141230.00
  }
]
```

**Business Logic:**
- JOIN `fact_orders` with `dim_date` on `date_key`
- GROUP BY `year`, `month`, `month_name`
- Filter: `order_date BETWEEN start AND end`
- Filter: `status IN ('delivered', 'shipped')`
- Sort: By month ascending

**Utility: ThemeContext**

**Architecture Components:**

1. **Frontend (React SPA)**
   - Single-page application
   - Client-side routing (3 views)
   - Recharts for data visualization
   - Theme context for light/dark mode

2. **Router (NGINX)**
   - Reverse proxy for frontend and backend
   - SSL termination (production)
   - Request routing by path prefix

3. **Backend (FastAPI)**
   - RESTful API with 7 endpoints
   - Automatic Swagger documentation
   - Backend abstraction (SQLite/Snowflake)
   - OAuth integration (production)

4. **Database (Snowflake/SQLite)**
   - Production: Snowflake Gold tables
   - Development: SQLite local file
   - Identical schema across environments

**Data Flow:**
1. User interacts with React frontend in browser
2. Frontend calls API endpoints via fetch
3. NGINX routes `/api/*` requests to FastAPI backend
4. Backend queries Snowflake (prod) or SQLite (dev)
5. Backend returns JSON response
6. Frontend renders charts/tables with Recharts
